## Current Module Graph

This is a concise direct-import snapshot, not the target design:

```text
lib
├─ runtime ───────────────┬─ runtime_interface, session_residency, session_execution
│                         ├─ durable_state, model_gateway, prompt, tools, workspace
│                         └─ agent_session_lifecycle, compaction, runtime_task, wire
├─ session_residency ─────┬─ durable_state, session_execution, conversation_storage
│                         └─ model_gateway, prompt, tools, workspace, wire
├─ session_execution ─────┬─ conversation_storage, live_conversation, durable_state
│                         ├─ model_gateway, prompt, session_ingress, tools
│                         └─ turn_execution_context, turn_item_interaction, wire
├─ conversation_storage ──┬─ agent_session_lifecycle, compaction, model_gateway, prompt
│                         └─ tools, turn_item_interaction, runtime_task, wire
├─ durable_state ─────────┬─ agent_session_lifecycle, conversation_storage
│                         └─ runtime_task, workspace, wire
├─ prompt ────────────────┬─ agent_session_lifecycle, compaction, live_conversation
│                         └─ model_gateway, skills, tools, workspace, wire
├─ model_gateway ─────────┬─ live_conversation, prompt, tools, wire
├─ tools ─────────────────┴─ runtime_task, workspace, wire
└─ wire ──────────────────┬─ runtime_interface and multiple domain modules
                          └─ reverse protocol dependency / cycle source
```

Observed risks are the `prompt ↔ model_gateway ↔ live_conversation` cycle, the broad `runtime/session_residency/session_execution` fan-in, and `wire` being imported by domain modules. The target graph is recorded as one edge per line in the migration review format:

```text
module | direct dependency | edge kind | canonical owner | status
runtime | session | orchestration | Runtime | target
session/actor | agent/runner | execution | SessionActor | target
agent/runner | prompt, model, tools, session/conversation | turn loop | ActiveTurn | target
model/providers | model/types, model/transport | adapter | ModelProvider | target
tools/builtins | tools/types, tools/context, workspace | adapter | Tool | target
prompt | model/types, tools/types, session/conversation DTO | projection | PromptBuilder | target
```

## Frozen P0 Decisions

- `session.json` persists an absolute `workspace_root`; no resolver/key mode is carried in parallel.
- AT-17 is validated through public consequences: close cancels/boundedly aborts, invalidates the old loaded handle, and permits a later load; no registry-map inspection.
- AT-20 is a P8/P9 static gate, not a behavioral test; the ignored test is only an inventory placeholder.
- Ignored skeleton bodies fail explicitly when selected; default gates compile them but do not claim behavior.
- P0 does not stage or edit the specification, production modules, Cargo metadata, README, or existing tests.

## Open Risks for Parent Review

1. The target `ProviderRegistry`/scripted-provider injection surface is not fully specified; AT-01/11/13 need one stable public test seam before P3.
2. The target snapshot shape does not clearly retain a recoverable `Completed`/`Cancelled` outcome after status returns to `Idle`, while AT-01/07 require that observation.
3. AT-15 must freeze whether `ResyncRequired` keeps the stream alive; the current baseline emits `Closed(Backpressure)` on broadcast lag.
4. `run_command` needs an explicit `coding_agent_local()`/PATH policy so AT-04 can find `cargo` after environment clearing.
5. Existing architecture docs and ADRs describe the pre-reset V2 contract; the branch-local authority declaration above is required until P9 rewrites them.
