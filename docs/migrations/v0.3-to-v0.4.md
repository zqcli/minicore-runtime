# Migration: v0.3 to v0.4

v0.4 is a breaking reset. This guide is for hosts and maintainers moving
from the v0.3 session-runtime core to the v0.4 flexible agent-loop core.

## What v0.4 Requires

- One-shot `AgentLoop` per run: the host builds a `LoopRequest` (its own
  history + fresh `UserInput` + `ExecutionConfig`) and holds the `LoopReport`
  it gets back.
- The host owns sessions, history, persistence, providers, and workspaces;
  the runtime owns only the live loop. See the
  [host boundary contract](../integration/host-boundary.md).
- A Tokio context, and Rust 1.85 or newer (MSRV 1.85).

## Not Migrated (Intentionally)

- **Session logs are not migrated.** `SessionLog` / `SessionManifest` /
  `SessionState` / durable conversation JSONL records and the old
  conversation ledger format are gone and are not re-created. Hosts that
  need a durable transcript must own the write path themselves.
- **`minicore-agent` is not migrated.** It still targets the v0.3 runtime
  surface and must be migrated separately after the runtime is stable.
- **Tool side effects and host logs are not atomic.** v0.4 makes this
  explicit: a tool can have side effects even when the host never logs the
  corresponding event, because events are best-effort. Hosts that require an
  atomic journal must wrap tool execution in their own transaction.
- **A current loop cannot be recovered.** There is no open/load/resume; a
  crashed or cancelled loop ends and the host starts a new one from the
  history it kept.

## What Changed

- `src/session`, `src/storage`, `src/conversation`, `src/agent`,
  `src/compaction`, `src/context`, and the old prompt/context pipeline are
  deleted. `UserInput` moved to `execution`; `Usage`/`UsageAccumulator` to
  `usage`.
- History is host data: `HistoryItem` in, `LoopReport::appended` out.
  Durable compaction was replaced by the `PromptProvider` seam; the built-in
  `DefaultPromptProvider` follows the host history projection rules.
- Control: `LoopHandle::update` and `::steer` apply at the next model
  request; the current tool batch keeps its producing request's snapshot;
  an update never keeps a final loop alive.
- Events are explicitly best-effort (`try_send`, bounded, `dropped_before`).
  The report is authoritative.
- The architecture gates were rewritten: `scripts/check_v04_architecture.py`
  (replacing the v0.3 scanner) and `scripts/check_docs.py` verify only the
  real boundaries (no session/durable/workspace/provider types, one
  `tokio::spawn` per loop, no async mutex, current docs).

## Upgrade Steps for a Host

1. Replace "open session + run turn" with "build `LoopRequest` + start one
   `AgentLoop` + `join`".
2. Own your history: keep a `Vec<HistoryItem>` (or your own store) and fold
   `report.appended` back in after each loop.
3. Replace durable compaction with a `PromptProvider` (start from
   `DefaultPromptProvider`).
4. Move session state, manifests, and transcript persistence into your own
   layer. There is no runtime API for them anymore.
5. Convert your old tool/model adapters to the `Tool` / `Model` seams
   (unchanged in spirit; see [model](../contracts/model.md) and
   [tool-policy-interaction](../contracts/tool-policy-interaction.md)
   contracts).
