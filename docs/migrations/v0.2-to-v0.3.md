# Migrating From v0.2 To v0.3

v0.3 is a direct breaking reset. There is no compatibility layer, alias, dual API, automatic store conversion, or deprecated bridge. Migrate the Host boundary and adapters explicitly.

## API Mapping

| v0.2 concept | v0.3 replacement |
| --- | --- |
| multi-session `Runtime` owner | one non-Clone `SessionRuntime` per loaded Session |
| `RuntimeClient`, manager handles, ID-routed commands | cloneable `SessionHandle` obtained from the exact SessionRuntime |
| Core Session list/create metadata/delete APIs | Host repository plus `HashMap<SessionId, SessionRuntime>` or equivalent |
| Core writer ownership/lease | Host repository or storage adapter lease acquired before open |
| `Runtime::submit(session_id, ...)` | `session.handle().submit(...)` |
| session-wide ambiguous cancel | exact `TurnHandle::cancel()` |
| snapshot/observation/cursor/gap/resync protocol | `SessionHandle::watch_state()`, one `take_events()`, `TurnHandle::wait()`, and transcript |
| durable/broadcast event history | best-effort single-consumer SessionEventStream; Conversation remains durable truth |
| ProviderRegistry/ModelResolver/model installation | one direct `Arc<dyn model::Model>` in SessionBindings |
| mutable provider/tool configuration | immutable SessionBindings for the loaded lifetime |
| concrete JSONL/Store selected by Core | Host-opened `Box<dyn SessionLog>` |
| Core Workspace and `ToolContext.workspace` | capability captured by each Host Tool or ContextProvider |
| builtin filesystem/process tools | Host Tool implementations registered in ToolSet |
| durable approval/input continuation | process-local PendingInteraction and typed answer; restart cancels unfinished work |
| subagent/agent graph type | ordinary Host RPC Tool when needed |
| generic lifecycle hooks/plugins | typed Port decorators or composites outside Core |

The removed `Runtime`, `ToolRegistry`, provider/store/workspace types, snapshots, observations, and legacy DTOs have no aliases in v0.3.

## Owner Migration

Instead of opening one Core manager, the Host constructs one owner per loaded Session:

```text
Host repository + lease
→ open SessionLog adapter
→ build SessionBindings
→ SessionRuntime::create or SessionRuntime::load
→ retain SessionRuntime in Host collection
→ use cloneable SessionHandle for request routing
→ explicit SessionRuntime::shutdown
→ release lease
```

Do not clone or hide SessionRuntime behind command routing that loses explicit shutdown ownership. A Host may wrap it in its own slot type, but exactly one path must consume the owner for shutdown.

## Storage Migration

v0.3 does not automatically read or transform the historical v0.2 store layout. Implement an external offline migration or export/import process:

1. stop v0.2 writers and acquire exclusive source access;
2. validate the old manifest/history using the old format implementation;
3. map only canonical user, assistant, tool-result, summary, and terminal facts;
4. construct a checked v3 SessionManifest and contiguous Conversation sequence;
5. initialize a new v0.3 SessionLog adapter and append validated batches;
6. verify replay through `SessionRuntime::load` before switching repository metadata;
7. retain the source for rollback/audit according to product policy.

Never copy pending Tool futures, approval continuations, actor mailboxes, event cursors, workspace paths, provider credentials, or owner task state into the v3 Conversation.

## Model Migration

Replace registry lookup with a direct Host adapter:

- implement `model::Model`;
- expose a checked host-neutral ModelDescriptor;
- map provider protocol into the typed ModelEvent grammar;
- construct structured `ModelError` via explicit constructors (`not_started`, `started`, `unknown`, `permanent`) with explicit `RetryHint` rather than deprecated shorthands;
- report DeliveryState honestly and remove hidden retries;
- bind one `Arc<dyn Model>` in SessionBindings;
- keep endpoints, credentials, HTTP clients, and provider metadata in the adapter.

A different model requires a different durable SessionSpec/load binding. There is no per-Turn model override or hot model swap.

## Tool And Workspace Migration

For each concrete tool:

1. move filesystem/process/RPC authority into the Host implementation;
2. implement the typed `Tool` Port;
3. return a checked ToolSpec and typed ToolExecutionOutcome;
4. register it explicitly in ToolSet;
5. implement ToolPolicy when enabled tools require policy;
6. remove assumptions about a Core Workspace or process service.

`ToolContext` provides only cancellation, deadline, and progress. If several tools share a workspace or limiter, capture an `Arc` to a Host-owned capability/decorator.

## Observation Migration

Use each mechanism for its defined purpose:

- `handle.state()` for an immediate current value;
- `handle.watch_state()` for current-state changes;
- `runtime.take_events()` once for lossy live presentation; use `StreamExt::next()` or `recv()` to consume it;
- `turn.wait()` for exact durable completion;
- `handle.transcript()` for confirmed durable history.

Do not rebuild a snapshot/resync protocol over EventStream. Events may be dropped; the next delivered envelope reports the preceding loss in `dropped_before`, which is informational rather than a replay cursor. `SessionRuntime` and `TurnHandle` are `#[must_use]` warnings, not lifecycle replacements: Drop remains cancellation-only for the runtime, and TurnHandle Drop does not cancel.

## Interaction And Restart Migration

Approval uses typed `AllowOnce` or `Deny`. ToolInput uses a typed text or choice answer. Do not send `"yes"`/`"allow"` strings or persist interaction answers as continuation tokens.

On restart, v0.3 replays durable Conversation only. Any unfinished Turn receives deterministic cancelled ToolResults for unresolved calls and one `CancelledByRestart` terminal. The Host should discard stale UI prompts and refresh state/transcript after load.

## Migration Checklist

- [ ] Replace every multi-session Core Runtime with Host-owned per-session owners.
- [ ] Add explicit writer lease and SessionLog adapter acquisition.
- [ ] Replace ID-routed submit/cancel with SessionHandle and TurnHandle.
- [ ] Replace snapshots/subscriptions with state watch, one event stream, Turn wait, and transcript.
- [ ] Bind Model and optional policy/context/compaction Ports directly.
- [ ] Move workspace, process, network, credential, and repository authority into Host adapters.
- [ ] Replace ToolRegistry/builtins with immutable ToolSet registration.
- [ ] Replace string approval and durable continuation with typed process-local interactions.
- [ ] Implement and verify an external data migration if historical sessions must be retained.
- [ ] Call explicit shutdown for every loaded owner before releasing its lease/runtime.
- [ ] Run the v0.3 acceptance and native CI matrix before publication.
