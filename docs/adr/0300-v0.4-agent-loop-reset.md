# ADR-0300: v0.4 Converge on the One-Live-Agent-Loop Boundary

- **Status**: Accepted
- **Date**: v0.4 (flex agent loop reset)
- **Deciders**: Runtime maintainers, following the
  [v0.4 implementation spec](../../minicore-runtime-v0.4-flex-agent-loop-reset-spec.md).

## Context

The v0.3 runtime owned a session runtime plus durable conversation, storage,
compaction, agent definitions, and provider plumbing. That surface grew
beyond what a reusable execution core should own, and it forced hosts (like
minicore-agent) to adopt the runtime's session model instead of their own.

## Decision

Converge the runtime on a single boundary: one live `AgentLoop`.

- The runtime owns only the live loop: model/tool iterations, streaming,
  cancellation, interaction, steering, and request-boundary configuration
  updates.
- The host owns sessions, history, persistence, providers, and workspaces.
  The loop consumes `LoopRequest { history, input, config }` and returns a
  `LoopReport`.
- Durable compaction is replaced by a `PromptProvider` seam with a strict
  default projection; there is no ledger, JSONL writer, session log, or
  durable conversation anywhere in the crate.
- Control is linearized on one short mutex (`update`/`steer`/final seal) plus
  a single-CAS `AtomicU8` cancel/finish state machine; events are
  best-effort `try_send`s; one `tokio::spawn` per loop.
- The tracker ADRs 0200/0203 and the whole session-era stack are removed;
  v0.3 evidence lives in `docs/archive` and `provider-gate`.

## Consequences

- Runtime maintenance is simpler: the crate dropped roughly two thirds of
  its production line count and test surface.
- Hosts regain ownership of their domain: `MemoryAgent`-style composition
  happens in host or example code, not in the library.
- The explicit cost: a current loop cannot be resumed, session logs are not
  migrated, tool side effects and host logs are not atomic, and
  `minicore-agent` must be migrated separately.
