# AgentRuntimeEvents 使用 EventMsg、配对生命周期和单 run 终态

AgentRuntimeEvents 是 Tauri/Vue 与 Ratatui 共享的 AgentRuntimeProtocol 的事件生命周期规则。我们决定让 `agent_runtime_protocol::EventStream` 传输 Codex-like `agent_runtime_protocol::Event { event_id, sequence, timestamp, workspace_id, session_id, run_id, command_id, msg }`；外层 `agent_runtime_protocol::Event` 负责顺序、路由、关联和重连水位，`agent_runtime_protocol::EventMsg` 负责业务事实。Rust 内部事件消息使用分组 enum，例如 `agent_runtime_protocol::EventMsg::Run(RunEvent::Started)`，UI/wire 事件类型使用 flat `snake_case`，例如 `run_started` 和 `tool_call_output_delta`；长生命周期对象使用明确的 started/delta/finished 配对；一次 run 只有一个终态事件 `run_finished { status }`，不再额外定义 `run_aborted` 这类第二终态。

这个决策参考了两类生产经验。pi-agent-core 的 `AgentEvent` 用 `agent_start`、`message_start/update/end`、`tool_execution_start/update/end`、`turn_end`、`agent_end` 表达运行流，pi coding-agent 在 session 层追加 `queue_update`、`compaction_start/end` 和 `auto_retry_start/end`，并由 `AgentSession` 处理持久化和对外订阅。Codex 使用 Submission Queue / Event Queue，把用户提交和 agent 事件分开，并在事件上带 submission id；Rust enum variant 使用 `PascalCase`，wire event type 使用 `snake_case`；长任务用 `ExecCommandBegin/OutputDelta/End`、`PatchApplyBegin/Updated/End`、`ItemStarted/ItemCompleted` 和 `TurnStarted/TurnComplete/TurnAborted` 表达可配对生命周期。

我们不直接照搬 pi 的 `agent_end` 或 Codex 的 `turn_*` 命名，因为本项目已经把一次 UI 请求到 Rig drive 的生命周期称为 `Run`，而 `turn` 在 Rig、模型调用、用户轮次和 session phase 中容易混淆。我们也不把 agent_runtime_protocol::Event 当成持久化日志；会话历史仍由 `SessionStorage` 的 append-only session entries 负责，事件流只负责 UI 实时更新和短期重连。`persistence_save_point` 是事件流中的持久化屏障，表示此前相关 session writes 已经形成可恢复边界。

结果是：UI reducer 可以依赖 `agent_runtime_protocol::Event` 外层字段做路由和去重，依赖 `sequence` 与 snapshot 水位做重连，依赖 lifecycle pair 关闭流式 UI 状态，依赖唯一 `run_finished { status }` 判断 run 终态。Rust 代码仍然通过 `agent_runtime_protocol::EventMsg` 分组 enum 获得类型安全和模块感，wire 层则通过 `snake_case` event type 对齐 serde、JSON schema、TS 生成、Codex 和 pi 的事件习惯。代价是 `AgentRuntime` / `SessionRuntime` 必须集中生成 `agent_runtime_protocol::Event` metadata 和维护顺序号，内部 `DriverEvent`、`Tools` update 和 `RuntimeHooks` typed result 不能直接透传给 UI，而要先由会话运行时归约成稳定的 `agent_runtime_protocol::EventMsg`。
