# ADR 0200: v0.3 Core Uses One Typed SessionRuntime Per Session

状态：Accepted

> Revised after the breaking v0.3 reset and P6 physical cleanup.

日期：2026-08-20

## Context

The current crate needs one source-accurate public boundary for a durable coding session. The previous repository surface combined transport payloads, platform entities, lifecycle routing, and multiple ownership models. Keeping aliases for that surface would make the v0.2 contract ambiguous and would preserve owners that are no longer compiled.

## Decision

The top-level Runtime facade and multi-session manager are deleted. The public boundary is the host-neutral Port set plus one non-Clone SessionRuntime owner for each created or loaded Session.

One loaded session has one actor, one bounded mailbox, one owned SessionLog adapter, and one active Turn at most. The turn runner and prompt builder remain private. Workspace, storage acquisition, concrete providers/tools, and multi-session management belong to the Host. No compatibility alias or alternate source graph is compiled by Core.

## Consequences

Hosts acquire SessionLog adapters and manage multiple SessionRuntime owners externally. Provider and tool installation remain explicit Host responsibilities.

See [architecture](../architecture.md), [module map](../modules/README.md), [root API](../../README.md), and [`src/lib.rs`](../../src/lib.rs).
